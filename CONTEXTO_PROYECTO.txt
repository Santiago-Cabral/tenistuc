1) QUÉ ES
--------------------------------------------------------------------------------
App de tenis amateur (Tucumán, Argentina): ranking ELO, rivales, desafíos,
chats 1:1, torneos con inscripción (habilitada por el organizador) y
notificaciones push.

Stack:
- Frontend: React Native + Expo (SDK 57) + Expo Router + Zustand
- Backend: Supabase (Auth + Postgres + Realtime + Edge Functions)
- Inscripciones: SIN pasarela de pago. El organizador habilita el lugar a mano
  y coordina el pago por fuera (efectivo/transferencia). La app sólo guarda el
  estado 'pending' | 'paid' de la inscripción. (MercadoPago fue ELIMINADO.)
- Login social: Google y Apple vía OAuth PKCE (nuevo).
- Notificaciones: tabla `notifications` + Expo Push (edge functions).
- Fuentes: Lexend (headlines) + Plus Jakarta Sans (body)
- Tema: theme "The Kinetic Court" en src/theme/index.ts

3) CONVENCIONES CRÍTICAS (¡NO ROMPER!)
--------------------------------------------------------------------------------
- TypeScript estricto. Verificar SIEMPRE con:  npx tsc --noEmit
- NO usar Deno en edge functions: patrón = async function handler(req: Request),
  env con process.env, y `export default { fetch: handler }`. Copiar de
  notify/index.ts o send-push/index.ts.
- Mensajes de UI en español argentino; identificadores de código en inglés.
- ALERTAS/DIÁLOGOS: usar SIEMPRE showAlert(...) de src/services/appAlert.tsx.
- UI: componentes de src/components/ui, tema de src/theme (nada hardcodeado).
- Supabase client: las queries se hacen con supabase-js. Lo que necesita
  service role (push) se hace en edge functions con SUPABASE_SERVICE_ROLE_KEY.
- `profiles.expo_push_token` NO es legible por el cliente: usar siempre
  PROFILE_COLUMNS en authStore y listas explícitas en los select.
- Inscripciones: sin pasarela. El organizador habilita con el toggle en la
  pestaña "Jugadores" (organizerTabs/payments.tsx); pasar a 'paid' dispara la
  notificación de inscripción confirmada.
